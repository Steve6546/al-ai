# قواعد النفق وحصة الطلبات + سقف الذاكرة — جولة 2026-11-14

**اقرأ هذا الملف عند العمل على `server/network.ts`، شاشة الشبكة، أو أي `npm test` / `npm run verify`.**
هنا **المفهوم والحدود**؛ التفاصيل القصصية في السجل اليومي. القواعد مُثبتة باختبارات
`apps/dashboard/test/network.test.ts` وبوابة `npm run verify`.

## المفهوم: «صحة النفق» ≠ «صحة الحساب»

- **النفق** = جلسة الوكيل (`/api/status`) + العنوان المعلن (`/api/tunnels`) + المنبع المحلي
  (`/api/health`). كلها تُقرأ من **loopback** ولا تمرّ على حافة ngrok ⇒ **لا تستهلك الحصة**.
- **الحساب** = حصة شهرية **20,000 طلب HTTP** للخطة المجانية. عند نفادها تردّ الحافة على
  **كل** طلب عام بـ`403` تحمل `ERR_NGROK_727`، بينما الوكيل نفسه ما زال `online`.
- الخلط بين الاثنين هو أصل العطب: المُعالج القديم قرأ الـ403 «الرابط لا يستجيب» فأعاد توليد
  الوكيل. إعادة التوليد لا تُصلح حساباً ⇒ حلقة لا نهائية (**437 عملية نفق في السجل**،
  والمراقب يعيد تشغيل اللوحة كل دقائق).

## الحدود (أرقام ملزمة، لا تُغيَّر بلا سبب)

| الحد | القيمة | لماذا |
|---|---|---|
| فحص الحيوية | كل 15 ثانية، **loopback فقط** | سريع، مجاني، يقود قرار إعادة التوليد |
| التحقق من الطرفين (عام) | **مرة/ساعة**، ومرة/6 ساعات أثناء نفاد الحصة | ≤120 طلب/شهر = 0.6% من الحصة؛ وهو الوحيد الذي يكشف `ERR_NGROK_727` |
| إعادة التوليد | فشلان متتاليان + **تهدئة 5 دقائق** | يمنع عاصفة إعادة التشغيل |
| استقصاء المتصفح: الصحة | 20 ثانية على loopback، **60 ثانية على الأصل العام**، و**صفر حين التبويب مخفي** | 20 ثانية/تبويب = 4,320 طلب/يوم |
| استقصاء شاشة الشبكة | ثانيتان أثناء `starting` فقط، ثم **60 ثانية**، وصفر حين التبويب مخفي | كان 2 ثانية **دائماً** = 30 طلب/دقيقة ⇒ ينفد الحصة في ~11 ساعة |
| اختبارات `node --test` | **عاملان كحد أقصى**، ~900 MiB لكل عامل، heap ≤768 MiB، رفض تحت 512 MiB حرّة | 20 معالجاً ⇒ 20 عامل tsx/jsdom ⇒ 8–15 GB على جهاز 16 GB |

**قاعدة ذهبية:** التطبيق **لا يرسل طلباً تلقائياً إلى أصله العام إلا التحقق المُحصّص مرة/ساعة**.
أي فحص ذاتي آخر يذهب إلى `127.0.0.1`. الرؤية/الحيوية محلية؛ الحقيقة العامة تُقاس بعينة واحدة.

## القواعد

1. **مصدر العنوان الحي = `GET http://127.0.0.1:4040/api/tunnels`** (`public_url`)، لا سجل
   `.al-tunnel.log` ولا مسبار عام. يعمل قبل `app.listen` لأن واجهة الوكيل مستقلة عن المنبع.
   السجل يبقى احتياطاً عند تعذّر الواجهة. **المنفذ 4040 يجب أن يبقى محلياً وحراً**؛ وكيل
   ثانٍ على الجهاز يسرقه.
2. **`isNgrokQuotaResponse(status, body)`** هو التصنيف الوحيد: `(403|429)` **و** وسم
   `ERR_NGROK_727` / `HTTP requests limit`. أي 403 آخر (بوابة المضيف، بروكسي، تطبيقنا)
   ليس حصة. **الحصة ⇒ `quotaExceeded: true` ⇒ `nextProbeState` يرفض إعادة التوليد**
   وتظهر رسالة صريحة + رابط `dashboard.ngrok.com/billing` في شاشة الشبكة.
3. **كل طلب تحقق عام يحمل `ngrok-skip-browser-warning`** ⇒ لا يُدفع طلب ثانٍ لصفحة
   التحذير الاعتراضية للخطة المجانية.
4. **`reconnecting` في `/api/status` = حيّ**، لا سبب لقتل الوكيل (ngrok يُصلح الجلسة بنفسه).
5. **`probeTunnelLocally` يرفض أي أصل غير loopback** (حماية SSRF): صحة النفق لا يجوز أن
   تتحول إلى طلب خارجي لعنوان من الإعدادات.
6. **نفاد الحصة لا يُعالَج بالكود**: انتظر دورة الفاتورة أو ترقِّ الخطة. حتى ذلك الحين
   يعمل `http://127.0.0.1:3000` والشبكة المحلية بكامل وظائفها. لا تَعِد بعكس ذلك.
7. **الاختبارات تمرّ كلها عبر `scripts/test-runner.mjs`** (ثلاث حزم). يختار التوازي من
   `os.freemem()` لا من عدد المعالجات، ويمرّر `NODE_OPTIONS=--max-old-space-size` لكل
   نسل. للتثبيت في CI: `AL_AI_TEST_CONCURRENCY` / `AL_AI_TEST_HEAP_MB` (مقيدان بنفس السقف).
   **كل متغيّر بيئة يقرأه الكود يجب أن يظهر في `.env.example`** — `env-template.test.ts`
   يفرض ذلك (`NODE_OPTIONS` أُضيف لهذا السبب).
8. **اختبار يكتب حالة حيّة يُعيدها، ويُصلح الجرح القديم**: `bot_identity` صفّ واحد يملكه
   النشر. قتل عامل بسبب نفاد الذاكرة بين `DELETE` و`after()` ترك الصفّ محذوفاً ⇒
   `presenceBefore = null` ⇒ الاستعادة تحذف مجدداً ⇒ «الصفّ البذرة موجود» يفشل للأبد.
   `before()` الآن يعيد بذرة السكيما ويتخذها لقطة. القاعدة: **الاختبار يُصلح حالةً كسرها
   اختبارٌ سابق، ولا يفشل بسببها**.

## أدلة الفحص (بدون حرق الحصة)

```bash
curl --noproxy '*' http://127.0.0.1:4040/api/status     # online/reconnecting
curl --noproxy '*' http://127.0.0.1:4040/api/tunnels    # public_url + metrics.http.count
curl --noproxy '*' http://127.0.0.1:3000/api/health     # 200 محلياً
npm run dev:status                                     # الخدمات والمنافذ
npm run verify                                         # 1040 اختبار، سقف ذاكرة مطبّق
```

**⚠️ لا `curl` بلا `--noproxy '*'`** — بروكسي الـsandbox يرد 502 مضلِّلاً.
**⚠️ `tsx` بلا hot-reload** ⇒ بعد أي تعديل خلفي أعد تشغيل اللوحة (المراقب المجدول يعيدها
خارج شجرة جلسة الأداة). دليل نجاح الإصلاح: `Adopted the live tunnel` يظهر **دون** مسبار
عام، وعدد `started tunnel` في السجل **لا يزداد**.

## MCP

`https://mcp.ngrok.com/mcp` مُسجَّل في `~/.workbuddy-ai/mcp.json` باسم `ngrok`
(`url` فقط، OAuth، بلا أسرار). يلزم **Trust + تسجيل الدخول من المتصفح** من إدارة الموصلات،
ثم يظهر `gw_list_endpoints` / `platform_whoami` وأدوات `ngrok:usage:read`. عند رفض
الصلاحيات ⇒ الخطة قد لا تشمل MCP: <https://ngrok.com/pricing>. بديل بلا OAuth =
PAT بقراءات فقط في `headers` (المستخدم يضعه بنفسه في الملف، **لا يُلصق في المحادثة**).
