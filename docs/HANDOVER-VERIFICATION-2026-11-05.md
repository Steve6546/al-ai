## 5. حالة الأمان والمصادقة و2FA

**ما هو مُثبت:**
- `GET /api/session` بجلسة حقيقية ⇒ `authenticated=true`؛ بلا جلسة ⇒ `401` على المسارات المحمية.
- كوكي الجلسة `__Host-al_ai_session` بـ `Secure + HttpOnly + SameSite=Lax + Path=/`؛ كوكي الحالة `__Host-al_ai_session_state` (`Max-Age=600`)؛ كوكي الدخول المعلَّق `__Host-al_ai_session_2fa` منفصل ولا يُصدر جلسة.
- حارس CSRF: كتابة بجلسة بلا `Origin` ⇒ 403، وبأصل أجنبي ⇒ 403، وبأصل الموقع ⇒ يمر للحارس التالي.
- OAuth: من الرابط العام `GET /auth/discord/login` ⇒ `302` إلى `https://discord.com/oauth2/authorize` بـ `client_id`, `redirect_uri` الخاص بالنفق, `scope=identify guilds`, `state`, `prompt=consent`.
- **استعلام بوابة Discord الرسمي** `GET /applications/@me` ب token البوت: التطبيق `1544750141112582187` يسجّل redirect URI اثنين: المحلي `http://localhost:3000/auth/discord/callback` والنفق `https://unquested-marline-nonrurally.ngrok-free.dev/auth/discord/callback`.
- `instance_settings.remote_access_verified_origin` = أصل النفق، و`markOriginVerified` **لا يُستدعى إلا بعد تبادل code ناجح** ⇒ `/api/network` يعيد `tunnelCallbackVerified=true`. هذا دليل على دخول Discord حقيقي اكتمل عبر النفق.
- **تنبيه منهجي:** تحميل صفحة `authorize` بلا جلسة يعيد 200 لكلٍّ من URI الصحيح وURI خاطئ (اختبرته كضابط سالب، نفس 74248 بايت). لذلك لم أعتبر الـ 200 دليلاً؛ الدليل هو استعلام البوابة الرسمي + الأصل الموثَّق.
- 2FA: الجداول `admin_two_factor` / `admin_two_factor_recovery` / `admin_two_factor_pending` موجودة في DB الحيّة بأعمدتها الصحيحة؛ الأسرار AES-256-GCM، رموز الاسترداد HMAC فقط، عدّاد TOTP يمنع إعادة التشغيل، 5 محاولات ثم إتلاف الطلب المعلَّق، انتهاء 5 دقائق، `COALESCE` يثبّت سرّ التسجيل عند إعادة المحاولة. `requiresSecondFactor` يغطّي `OWNER_ID` وملك/مدير أي سيرفر، و**يفشل مغلقاً** إذا تعذّرت قراءة القائمة. لا تبقّى أي صفوف من فحوص 2FA أو مسبار التجاوز (0 معلَّق).
- اختبارات 2FA + منع التجاوز + OAuth لم تُضعِف أي حارس، ولم تُترك بعدها بيانات اختبار.

**⚠️ ما لم يكتمل (يحتاج المشغّل):**
1. **`admin_two_factor` = 0 صف**：لا مسؤول حقيقي مسجَّل بعد. التسجيل يحدث عند **أول دخول حقيقي** للمشغّل (تُعرض مفاتيح `otpauth://` وعشرة رموز استرداد مرة واحدة). لم أُنشئ حساباً وهمياً لأدّعي الإعداد، لأن إتمام الدخول يتطلّب بيانات حساب Discord الخاصة بالمشغّل.
2. **3 جلسات حيّة للمالك** (`♪Klaus`, `OWNER_ID` مطابق) صُكّت **قبل** شحن 2FA، ومستثناة من الفرض بحكم التوافقية المقصودة (`README`: «تمكينها لا يُخرج المشغّل أثناء العمل»). ⇒ عملياً هذه الجلسات تدخل بلا عامل ثانٍ. **لم أُبطلها لأنها بيانات المستخدم**؛ التوصية: `POST /auth/logout` من كل جهاز ثم دخول حقيقي واحد يسجّل المفتاح.
3. العمل بأكمله (2FA + إصلاحات هذه الجولة) **غير ملتزم بـ git**. لم أُنشئ commit دون إذن صريح.
4. تاريخ Git القديم `7d67921` يحتوي مفاتيح Supabase **publishable** (عامة بالتصميم) داخل `.env` تاريخي؛ لا قيمة سرية حالية في أي blob. لم يُعَد كتابة التاريخ.

- **✅ أُصلحت** جميع مخالفات `check:ui:live` الـ11 (تباين، ترتيب عناوين، تركيز لوحة المفاتيح) — الفحص الرسمي الآن **EXIT 0** بـ **77 PASS / 0 FAIL** و20 فحص axe نظيف، بعد أن كان 68 PASS / 9 FAIL.
- **✅ يعمل** المشروع محلياً (DB + BFF + بوت) وعبر HTTPS عام بجلسة حقيقية، مع تطابق بصمة الحزمة المخدومة.
- **⚠️ لا أُعلن جاهزية إنتاجية 100%**: تبقّى تسجيل مسؤول حقيقي في 2FA، وإبطال الجلسات السابقة له، والتزام العمل في git — وكلها تتطلّب قرار/دخول المشغّل، ولم أستبدلها ببيانات وهمية.

**التنظيف:** أوقفت مهامي الخلفية المؤقتة فقط (مسبار القياس، فحوص المتصفح، عمليات الاختبار التي علّقتها مهلتي). **أبقيت مجموعة `dev` حيّة عن قصد** لأنها تخدم رابطَي المعاينة؛ ولم ألمس عمليات المستخدم أو بياناته أو سجلّاته.
